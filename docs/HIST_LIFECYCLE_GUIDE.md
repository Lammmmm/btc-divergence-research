# Hist 背离全过程副图 v1

文件：`pine/Hist_Divergence_Lifecycle_v1.pine`。Pine Script v6，独立副图。只保留 **MACD Histogram（Hist）普通背离**，不是 MACD 线背离，也不是新增交易策略。

已有历史结果支持优先观察日线 Hist，不能得出只有 Hist 有效或 4H 同样可靠的结论。本指标把信号、价格结构跟踪和结果分开显示，帮助复盘和日常观察，不把研究中的成功率显示成某一笔信号的实时胜率。

## 看图顺序

| 阶段 | 图上显示 | 含义 |
|---|---|---|
| 观察中 | 普通 Hist 柱，面板显示暂无有效背离 | 尚无可跟踪信号 |
| 潜在形态 | 底部淡黄色/淡蓝色圆点，面板“潜在底/顶背离” | 当前价格与 Hist 呈潜在普通背离，尚未正式确认，盘中可能消失 |
| 潜在撤销 | 底部灰色叉号 | 上一潜在形态消失或转向，不计正式事件失败 |
| 背离生效 | 黄/蓝生效标签、带事件编号；底部同色状态带 | 底背离黄色、顶背离蓝色；已收盘确认并冻结结构，反转尚未确认 |
| 等待中 | 状态带持续；面板显示价位、位置进度和已等待根数 | 允许长期横盘，不设时间到期；新提示不会改动当前边界 |
| 反转确认 | 绿色标签与顶部菱形 | 收盘突破冻结确认位；本次结构事件结束 |
| 结构失效 | 红色标签与顶部叉号 | 收盘越过冻结失效位；本次事件结束，之后反转不会改写原结果 |

“背离前”只能显示**当时已观察到的潜在形态**，不能提前知道哪次一定成为背离。正式生效不保证此前一定出现一根可见的潜在标记；例如同一收盘才确认了所需旧枢轴。

没有背离连接斜线，没有贯穿副图的背景竖条，不修改主图 K 线。零轴和 MACD Histogram 柱属于正常指标图形。MACD/Signal 两条曲线默认关闭，可在设置中打开。

## 判定与进度

底背离正式生效时，用原背离起点至提示确认根（包含两端）的最高价、最低价冻结结构区间，同时冻结 ATR(14)。

- 后续收盘 **> 区间最高价**：反转确认。
- 后续收盘 **< 区间最低价 − 0.5 × 当时 ATR**：结构失效。
- 顶背离反向；相等不触发；影线穿越不独立触发结果。
- 正式事件最早在生效后的下一根收盘产生结果。
- 全部方向共用一个活动事件；未结束时所有后续提示只累计忽略次数。同一收盘可以结束旧事件并启动下一事件，编号和标签分别保留。

**价格进度不等于成功概率。** 提示收盘价为零点：价格向确认方向移动，用“当前顺向距离 / 提示价到确认位的距离”计算；向失效方向移动，用“当前逆向距离 / 提示价到失效位的距离”计算。面板以“向确认”或“向失效”展示，数值可以增加、减少及改变方向。未正式收盘完成的事件最多显示 99.9%；盘中越界时明确显示“尚未收盘”。

已等待根数、天数与最大逆向波动只更新已收盘路径；当前未收盘柱的价格位置可以实时变化。最大逆向波动是相对提示价的行情波动，不是交易或账户回撤。

## 安装与参数

1. TradingView 选择 `BINANCE:BTCUSDT.P` 的标准蜡烛图，切换日线或 4 小时。
2. Pine 编辑器 → 创建新的 → 指标，将文件完整复制进去，保存并“添加到图表”。这是独立脚本，不需要覆盖原聚合指标。
3. 拉高 Hist 副图，建议至少约 220 像素，或点击窗格右上角的最大化按钮。紧凑面板默认 8 行；开启“展开面板详细数据”后为 14 行，需要更高副图。
4. 黄色代表底背离，蓝色代表顶背离，绿色代表完成确认，红色代表失效。把鼠标放在历史事件标签上可查看该事件冻结价位。

默认参数：MACD 12/26/9；枢轴确认根数 5；最近 10 个枢轴；最大跨度 100；价格源固定 Close；仅 Regular；始终等待收盘确认；结构缓冲 0.5 ATR；跟踪起始时间 2021-01-01 UTC。修改参数后不可套用原报告的统计比例。缓冲不是交易止损指令。

默认紧凑面板包含当前阶段、价格进度、确认位、失效位、已等待时间、最近完成事件和实时收盘状态。详细面板另列距边界距离、提示价、冻结 ATR、最大逆向波动、忽略次数及参数口径。

可选警报有：底背离正式生效、顶背离正式生效、结构反转确认、结构失效。需要用户自行在 TradingView 创建警报，建议“每根 K 线收盘一次”。本次没有代替用户创建通知或下单。

## 历史一致性和限制

2026-10-17 已在 TradingView 创建并保存独立脚本“Hist 背离全过程 · 结构进度 v1”，使用 BINANCE:BTCUSDT.P 日线及 4H 编译运行。保存版本 2 的完整源码已通过编辑器复制，与本地文件逐字符比对一致（统一换行后 16,001 字符）。运行截图保存在 `reports/hist_lifecycle_1d_tradingview.png` 和 `reports/hist_lifecycle_4h_tradingview.png`。这确认了真实 Pine 编译和当前图表运行，不等于所有历史结果已完成跨平台对账。

确认信号沿用原聚合脚本 Hist 分支的价格枢轴、转向 OR 条件及虚拟连线穿越检查。新副图只在收盘时提交枢轴、启动事件和确认结果；标签放在当时的确认根，不回画到旧拐点。实时潜在形态和进度可以撤销，不能声称所有可视元素永不变化。

原 Binance 下载快照的两个 4H 异常价位曾在离线研究中隔离。产品读取 TradingView 当前图表数据，没有把下载快照的异常时间硬编码成“该时刻永远无效”。因此，即使规则相同，实际图表与原研究仍可能因数据源、历史修订、预热范围及已加载历史长度而不同。差异记录见 `results/hist_lifecycle/quarantine_comparison_*.json`。

使用已保存行情进行离线流式重放时，日线 39 个事件与已发布 Hist 结构研究一致；4H 仍为 202 个事件、83 成功/118 失败/1 待定，但因不隔离那两根下载异常行情，其中 1 个失败事件的启动时点与旧研究不同。不能只凭汇总数字相同就声称逐条一致。新增加的“潜在形态”仅用于观察，其预测准确率尚未回测。

离线检查：`python run_hist_lifecycle.py`。包含 8 项状态机测试以及 1D/4H 全部已保存信号跨度的核对；逐根镜像记录在 `results/hist_lifecycle/timeline_*.jsonl.gz`。这是 Python 流式规则与已保存研究的核对，不是 Pine 的本地执行，也不等于 TradingView 全历史导出对账。

Pine 的 `Audit ...` 图形仅显示在数据窗口，可用于之后逐根对账，不挤压 Hist 的纵轴。历史标签最多保留平台允许的近期 200 个；删除早期可见标签不改变事件计算。图表加载历史不足会影响初始 EMA、枢轴及正在跟踪的事件，因此事件编号不是跨不同历史范围的永久ID。
